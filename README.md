# Кроссплатформенное приложение для бронирования муниципальных спортивных площадок образовательными учреждениями

Курсовой проект по разработке многопользовательской информационной системы для координации и бронирования муниципальной спортивной инфраструктуры школами, гимназиями, лицеями и детско-юношескими спортивными секциями г. Новосибирска.

---

## 📌 Состав и архитектура системы

Проект спроектирован с расчетом на работу единого серверного бэкенда и общей базы данных с несколькими типами клиентов:
1. **Серверная часть:** REST API (JSON) на Node.js и Express с доступом к СУБД PostgreSQL через драйвер `pg`.
2. **Веб-клиент:** Адаптивный веб-сайт (HTML5 + Tailwind CSS + Vanilla JS, Leaflet OpenStreetMap, SweetAlert2), раздаваемый Express-сервером из директории `public/`.
3. **Мобильный клиент (Android):** REST API полностью подготовлен для взаимодействия с мобильным приложением (стандартизированные JSON-ответы, JWT-авторизация в заголовке `Authorization: Bearer <token>`, ISO 8601 даты).

---

## 🛠️ Стек технологий

- **Сервер:** Node.js (v18+ / v24), Express 4, `pg` (пул соединений), `bcrypt`, `jsonwebtoken`, `dotenv`, `cors`, `zod`.
- **База данных:** PostgreSQL 18. Реляционная схема 3НФ, расширение `btree_gist`, интервальные ограничения исключения `EXCLUDE USING gist`, триггеры целостности PL/pgSQL, русскоязычные комментарии `COMMENT ON`.
- **Фронтенд:** Чистый JavaScript (ES6+), Tailwind CSS (CDN), Leaflet.js (интерактивные карты OpenStreetMap без платных ключей), Axios, SweetAlert2 (`Swal.fire`).

## ⚙️ Установка и запуск

### 1. Предварительные требования
- Установлен **Node.js** версии 18 или выше (проверка: `node -v`).
- Установлен и запущен сервер **PostgreSQL** (проверка: `psql --version`).

### 2. Настройка конфигурации (.env)
В корневой папке `D:\cpj` создайте файл `.env` на основе `.env.example`:
```env
PORT=3000

DB_HOST=localhost
DB_PORT=5432
DB_NAME=sport_booking
DB_USER=sport_booking_user
DB_PASSWORD=sport_booking_pass_2026

JWT_SECRET=super_secret_jwt_key_sport_booking_2026_coursework
JWT_EXPIRES_IN=7d

PG_SUPERUSER=postgres
PG_SUPERUSER_PASSWORD=12345
```

### 3. Инициализация БД и миграции
Выполните команды в терминале:
```powershell
# Первоначальное создание БД и пользователя приложения
node db/init_db.js

# Применение миграций схемы (создание таблиц, индексов, триггеров)
npm.cmd run db:migrate

# Заполнение тестовыми данными г. Новосибирска
npm.cmd run db:seed

# Запуск тестов целостности и защиты от двойного бронирования в БД
node db/test_db.js
```

### 4. Запуск сервера и открытие сайта
```powershell
npm.cmd start
```
Сервер запустится по адресу: **http://localhost:3000**  
Откройте данный адрес в любом современном веб-браузере.

## 🛡️ Защита от двойного бронирования и конфликтов

В проекте реализована **двухуровневая защита целостности данных**:

### Уровень 1: СУБД PostgreSQL (надежная аппаратная гарантия)
1. Подключено расширение `btree_gist`.
2. На таблицу `bookings` наложено EXCLUDE-ограничение:
   ```sql
   CONSTRAINT ex_booking_no_overlap EXCLUDE USING gist (
       venue_id WITH =,
       tstzrange(start_at, end_at) WITH &&
   ) WHERE (status != 'cancelled');
   ```
   Даже если два пользователя одновременно отправят запросы на бронирование одной площадки на один и тот же час, СУБД отклонит второй запрос с ошибкой `23P01` (`exclusion_violation`).
3. Созданы двусторонние триггеры PL/pgSQL:
   - `trg_booking_block_conflict`: запрещает создание брони на площадку в период планового ремонта (`venue_blocks`).
   - `trg_block_booking_conflict`: запрещает администратору устанавливать блокировку на время, когда уже есть активные подтвержденные бронирования школ.

### Уровень 2: Сервер Express
- Централизованный перехватчик `src/middleware/errorHandler.js` распознает код ошибки `23P01` и возвращает клиенту корректный статус **`409 Conflict`** с понятным русскоязычным сообщением.

## 📡 Документация REST API

Все эндпоинты принимают и возвращают данные в формате JSON с префиксом `/api`.

### 1. Авторизация и профиль (`/api/auth`)
- `POST /api/auth/register` — Регистрация нового пользователя.
- `POST /api/auth/login` — Вход в систему с выдачей JWT токена.
- `GET /api/auth/me` *(требует Bearer токен)* — Получение данных текущего пользователя.
- `GET /api/auth/dictionaries` — Список ролей, образовательных учреждений и видов спорта для выпадающих списков.

### 2. Спортивные площадки (`/api/venues`)
- `GET /api/venues` — Список площадок с фильтрами (`sport_type_id`, `has_lighting`, `has_fence`, `search`).
- `GET /api/venues/:id` — Детальная карточка площадки, фотогалерея, перечень инвентаря.
- `GET /api/venues/:id/availability?from=...&to=...` — Занятость площадки (активные брони и блокировки на ремонт).

### 3. Бронирования (`/api/bookings`)
- `POST /api/bookings` *(требует Bearer токен)* — Создание заявки на бронирование площадки (возвращает 201 Created или 409 Conflict при накладке).
- `GET /api/bookings/my` *(требует Bearer токен)* — Список бронирований текущего учителя/школы.
- `PATCH /api/bookings/:id` *(требует Bearer токен)* — Перенос времени бронирования (с проверкой на отсутствие конфликтов).
- `DELETE /api/bookings/:id` *(требует Bearer токен)* — Отмена бронирования (перевод в статус `cancelled` и освобождение слота).

### 4. Администрирование (`/api/admin`) — *доступно ролям admin и venue_manager*
- `GET /api/admin/venues`, `POST /api/admin/venues`, `PUT /api/admin/venues/:id`, `DELETE /api/admin/venues/:id` — Управление спортивными площадками.
- `GET /api/admin/bookings` — Просмотр всех бронирований школ с фильтрацией по статусу.
- `PATCH /api/admin/bookings/:id/status` — Изменение статуса бронирования (`confirmed`, `cancelled`).
- `GET /api/admin/blocks`, `POST /api/admin/blocks`, `DELETE /api/admin/blocks/:id` — Управление сервисными блокировками (ремонт).
- `GET /api/admin/users` *(только для admin)* — Список зарегистрированных пользователей и их статистика.

## 🧪 Автоматизированные тесты

Для проверки работоспособности всех компонентов перед защитой подготовлены проверочные сценарии:

1. **Тестирование базы данных:**
   ```powershell
   node db/test_db.js
   ```
   Проверяет количество записей, триггеры и гарантированное падение СУБД с ошибкой при попытке создания пересекающейся брони.

2. **Тестирование REST API:**
   ```powershell
   node test_api.js
   ```
   Проверяет авторизацию, выдачу токенов, ролевую модель, каталог, создание брони, попытку вызвать конфликт 409 и отмену бронирования.

3. **Тестирование веб-страниц:**
   ```powershell
   node test_static.js
   ```
   Проверяет раздачу сервером Express всех HTML страниц, CSS стилей и клиентских JS скриптов (HTTP 200 OK).
