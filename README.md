# SportBook — Кроссплатформенное приложение для бронирования муниципальных спортивных площадок образовательными учреждениями

Курсовой проект по разработке многопользовательской информационной системы для координации и бронирования муниципальной спортивной инфраструктуры школами, гимназиями, лицеями и детско-юношескими спортивными секциями г. Новосибирска.

---

## 📌 Состав и архитектура системы

Проект спроектирован с расчетом на работу единого серверного бэкенда и общей базы данных с несколькими типами клиентов:
1. **Серверная часть:** REST API (JSON) на Node.js и Express с доступом к СУБД PostgreSQL через пул соединений драйвера `pg`.
2. **Веб-клиент:** Адаптивный веб-сайт (HTML5 + Tailwind CSS + чистый JavaScript без тяжелых SPA-фреймворков, интерактивная карта Leaflet на свободной подложке OpenStreetMap с кластеризацией markercluster и Esri fallback, уведомления SweetAlert2), раздаваемый Express-сервером из директории `public/`.
3. **Мобильный клиент (Android):** REST API полностью подготовлен для взаимодействия с мобильным клиентом (единый JSON формат, авторизация по стандарту JWT `Authorization: Bearer <token>`, временные метки ISO 8601).

## 🛠️ Стек технологий

- **Сервер:** Node.js (v18+ / v24), Express 4, `pg` (пул соединений), `bcrypt`, `jsonwebtoken`, `dotenv`, `cors`, `zod`.
- **База данных:** PostgreSQL 18. Реляционная схема 3НФ, расширение `btree_gist`, интервальные ограничения исключения `EXCLUDE USING gist`, триггеры целостности PL/pgSQL, русскоязычные комментарии `COMMENT ON`.
- **Фронтенд:** Чистый JavaScript (ES6+), Tailwind CSS (CDN), Leaflet.js (интерактивные карты на тайлах OpenStreetMap с кластеризацией `leaflet.markercluster` и ограничением территории Новосибирска), Axios, SweetAlert2 (`Swal.fire`).
- **Цветовая палитра:** Единая зелёная гамма:
  - Основной акцент: `#16a34a` (green-600) / `#15803d` (green-700)
  - Тёмный акцент: `#166534` (green-800)
  - Светлый фон: `#f0fdf4` (green-50)
  - Рамки и разделители: `#d1fae5` (green-100)
  - Текст: `#1f2937` (gray-800)
- **Изображения:** 20 локальных векторных SVG-схем спортивных площадок (вид сверху, 800x600, соотношение 4:3) в `public/img/venues/<sport>/<1..4>.svg` + поддержка пользовательских фото в `public/img/venues/custom/<id>/` (полная автономность без внешних фотохостингов).

## 🏃 Виды спорта в системе SportBook

В системе зафиксирован нормализованный перечень из 5 видов спорта (таблица `sport_types`):
1. **Футбол** — поля и мини-футбольные площадки с искусственной травой и мачтовым освещением.
2. **Баскетбол** — площадки с амортизирующим полиуретановым покрытием и щитами с кольцами.
3. **Волейбол** — площадки со стойками, сетками и песчаным или резиновым покрытием.
4. **Универсальная площадка** — многофункциональные комплексы для игровых видов спорта с круговым ограждением.
5. **Легкая атлетика** — стадионы с круговыми беговыми дорожками (тартан/резина), прыжковыми ямами, турниками и гимнастическим сектором ОФП для сдачи норм ГТО.

## 🗺️ Интерактивная карта

- **Картографический движок:** Leaflet с расширением `leaflet.markercluster` для группировки меток при отдалении.
- **Подложка тайлов:**
  - **Основная:** OpenStreetMap (`https://tile.openstreetmap.org/{z}/{x}/{y}.png`, maxZoom: 19, `referrerPolicy: 'origin'`).
  - **Резервная (fallback):** Esri World Street Map (`https://server.arcgisonline.com/ArcGIS/rest/services/World_Street_Map/MapServer/tile/{z}/{y}/{x}`). Переключение происходит автоматически при 5 последовательных ошибках загрузки тайлов (`tileerror`).
  - Сторонние платные сервисы (CARTO) и водяные знаки API полностью устранены.
- **Границы просмотра:** Карта строго зафиксирована в пределах территории Новосибирска:
  - Центр: `[55.03, 82.92]`, стартовый зум: 11, минимальный зум: 10.
  - Ограничение границ: `maxBounds: [[54.80, 82.60], [55.20, 83.30]]`, `maxBoundsViscosity: 1.0`.
  - Перемещение за пределы Новосибирской агломерации заблокировано.
- **Атрибуция:** Чистая текстовая атрибуция `© участники OpenStreetMap` со ссылкой на копирайт; флаги и префиксы библиотеки отключены (`L.control.attribution({ prefix: false })`).
- **Маркеры и кластеры:**
  - Зеленые кластерные круги (`.marker-cluster-sport`) с плавной анимацией и паутинным раскрытием (`spiderfy`).
  - 5 типов индивидуальных SVG-пинов с контрастными пиктограммами для каждого вида спорта (футбол, баскетбол, волейбол, универсальная площадка, легкая атлетика).
  - Двусторонняя связь карты и списка: клик по карточке центрирует карту, раскрывает кластер и открывает попап; клик по маркеру подсвечивает карточку площадки в каталоге.

## 🛡️ Защита от двойного бронирования и конфликтов

В проекте реализована **двухуровневая защита целостности данных**:

### Уровень 1: СУБД PostgreSQL (надежная аппаратная гарантия)
1. Подключено расширение `btree_gist`.
2. На таблицу `bookings` наложено EXCLUDE-ограничение:
   ```sql
   CONSTRAINT ex_booking_no_overlap EXCLUDE USING gist (
       venue_id WITH =,
       tstzrange(start_at, end_at) WITH &&
   ) WHERE (status != 'cancelled');
   ```
   Если два пользователя одновременно отправят запросы на бронирование одной площадки на один и тот же час, СУБД отклонит второй запрос с ошибкой `23P01` (`exclusion_violation`).
3. Двусторонние триггеры PL/pgSQL:
   - `trg_booking_block_conflict`: запрещает создание брони на площадку в период планового ремонта (`venue_blocks`).
   - `trg_block_booking_conflict`: запрещает администратору устанавливать блокировку на время, когда уже есть активные подтвержденные бронирования школ.

### Уровень 2: Сервер Express
- Централизованный перехватчик `src/middleware/errorHandler.js` перехватывает код ошибки `23P01` и возвращает клиенту статус **`409 Conflict`** с понятным русскоязычным сообщением.

## 📡 Документация REST API

Все эндпоинты принимают и возвращают данные в формате JSON с префиксом `/api`:

### 1. Авторизация и профиль (`/api/auth`)
- `POST /api/auth/register` — Регистрация нового пользователя.
- `POST /api/auth/login` — Вход в систему с выдачей JWT токена.
- `GET /api/auth/me` *(Bearer токен)* — Получение данных текущего пользователя.
- `GET /api/auth/dictionaries` — Список ролей, ОУ и видов спорта.

### 2. Спортивные площадки (`/api/venues`)
- `GET /api/venues` — Список площадок с фильтрами (`bank`, `district`, `sport_type_id`, `has_lighting`, `has_fence`, `search`, `limit`, `offset`).
- `GET /api/sport-types` — Список всех доступных видов спорта.
- `GET /api/venues/:id` — Детальная карточка площадки, фотогалерея, перечень инвентаря.
- `GET /api/venues/:id/availability?from=...&to=...` — Занятость площадки (брони и блокировки на ремонт).

### 3. Бронирования (`/api/bookings`)
- `POST /api/bookings` *(Bearer токен)* — Создание заявки на бронирование (возвращает 201 Created или 409 Conflict при накладке).
- `GET /api/bookings/my` *(Bearer токен)* — Список бронирований текущего преподавателя.
- `PATCH /api/bookings/:id` *(Bearer токен)* — Перенос времени бронирования (с проверкой отсутствия конфликтов).
- `DELETE /api/bookings/:id` *(Bearer токен)* — Отмена бронирования (перевод в `cancelled` и освобождение слота).

### 4. Администрирование (`/api/admin`) — *роли admin и venue_manager*
- `GET /api/admin/venues`, `POST /api/admin/venues`, `PUT /api/admin/venues/:id`, `DELETE /api/admin/venues/:id` — Управление объектами (с поддержкой `bank` и `district`).
- `GET /api/admin/bookings` — Просмотр всех заявок школ с фильтрацией по статусу.
- `PATCH /api/admin/bookings/:id/status` — Подтверждение или отклонение бронирования.
- `GET /api/admin/blocks`, `POST /api/admin/blocks`, `DELETE /api/admin/blocks/:id` — Управление блокировками на ремонт.
- `GET /api/admin/users` *(только admin)* — Список зарегистрированных пользователей и статистика.
